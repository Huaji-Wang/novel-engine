# 叙事弧规划参考（对齐 ainovel-cli architect-long / outline-template）

本参考用于 engine 中**卷内叙事弧（Arc）**的规划、展开与弧末沉淀。与「角色卡 arc 字段（人物弧线）」无关。

## 弧是什么

每一弧像**一个可独立成立的小故事**：

- 有明确 **goal**（本弧要达成什么叙事结果）
- 有明确 **阻力**（谁/什么规则/什么代价在挡路）
- 有 **阶段转折**（起承转合，不是匀速推进）
- 有 **结果与代价**（弧结束时哪些状态不可逆地变了）

## 弧级检查清单（规划每条弧时必须能回答）

- 这条弧的明确目标是什么？
- 阻力来自谁、什么规则、什么代价？
- 转折点是什么？
- 这条弧结束后，哪些状态发生了不可逆变化？
- 本弧如何服务所在卷的 theme，又如何为下一弧/卷末钩子蓄势？

## 弧级节奏密度

每弧遵循 **铺垫 → 积累 → 爆发 → 收获** 的节奏循环。常见弧型（章数为尺度参考，可微调）：

- **成长突破弧**（10–15 章）：能力不足/准备 → 外部考验 → 关键突破 → 展示收获
- **竞技对抗弧**（12–20 章）：赛前准备/情报 → 多轮对决 → 决胜与奖惩
- **探索发现弧**（15–25 章）：情报与组队 → 层层深入 → 最终发现
- **恩怨冲突弧**（8–12 章）：矛盾积累 → 冲突爆发 → 多方博弈 → 解决与后果
- **日常过渡弧**（5–8 章）：角色发展/社交/伏笔/休整，为下一高潮弧蓄势

原则：

- **重大转折是整个弧的高潮**，不是单章事件
- 主弧 `estimated_chapters` 不宜低于 **8**（太短无法展开节奏循环）；过渡弧可 5–8
- 弧内章节要有起伏，**禁止匀速平推**
- **强钩子约每 2–3 章一次**；**弧的最后一章必须留强钩子**，承接下一弧
- **不同类型的弧应交替使用**，避免节奏单调

## 骨架弧 vs 已展开弧

- **骨架弧（skeleton）**：仅有 title、goal、estimated_chapters；写作推进到该弧前再展开
- **展开弧（expand）**：为该弧内每一章写出 title、core_event、hook、scenes（或等价细纲字段）

## 展开弧（expand_arc）时的要求

1. 根据 **弧 goal + 前文发展 + 角色当前状态** 设计详细章节
2. 实际章数可偏离 estimated_chapters，但须保持**节奏密度**（仍须完整走完铺垫→积累→爆发→收获）
3. **参考前一弧**的节奏、标题语感与风格；延续前弧留下的伏笔和钩子
4. 判断本弧适合**回收哪些未回收伏笔**，并在章节中安排
5. 每章必须**服务于弧 goal**；每章须有一个不可删除的事件推进

## 章节 title 硬约束（展开弧时尤其严格执行）

- **长短必须有起伏，禁止机械对齐**：同一弧内标题自然交错（如：借炉 / 同行的牙 / 夜里翻旧册），切忌全弧统一字数
- 与前文保持同一**语感与气质**（雅俗、意象密度、文白倾向）；气质一致 ≠ 字数一致
- 只允许**名词短语或动名词短语**；禁止完整句，禁止内含逗号、句号、冒号、引号
- 标题是读者记住本章的锚点；**主题/冲突/升华属于 core_event 和 hook**，不要塞进 title

## 卷内多弧时的分工

- 各弧 goal **不得重复**同一冲突类型（避免「换皮打怪」）
- 同卷内弧与弧之间：上一弧的未竟线/钩子应被下一弧 goal 承接或转化
- 第一弧（或 append 后新卷第一弧）须**自然衔接**前卷/前弧结尾

## 与 world_rules / 角色的关系

- 弧目标须受 **world_rules（世界观约束）** 限制，不能凭空突破已建立规则
- 角色调度与 **characters** 一致；弧内关系变化须可在角色弧线中追溯
